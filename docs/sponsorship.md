# Спонсорство Telemt

Floating IP не требуется для первой регистрации: Commander использует текущий
адрес прокси (`floating_ip`, если он задан, иначе `proxy_ip`) и MTProto-порт агента.
Основной Management IP при этом не меняется. Адрес WEB-входа и MTProto-порт
не следует путать: успешный HTTPS-ответ не подтверждает ни передачу MTProto,
ни показ спонсорского канала.

## Порядок пилота

1. Сохранить отдельную авторизованную интеграцию Telethon, MTProto-secret и
   публичный спонсорский канал в настройках агента.
2. Проверить существующие регистрации в MTProxybot, чтобы избежать дубликата.
   Пустая история AutoIP сама по себе не доказывает отсутствие регистрации в боте.
3. Получить отдельное подтверждение оператора на реальный диалог MTProxybot и
   изменение `general.ad_tag` действующего Telemt. Установка агента сама по себе
   не разрешает запись конфигурации: нужны оба разрешения защищённого helper.
4. После подтверждения зарегистрировать текущий IPv4:MTProto-порт с существующим
   базовым secret, получить ad_tag и назначить канал. Неизвестные ответы бота
   останавливают сценарий; повторная регистрация при неопределённом результате
   запрещена до ручной сверки.
5. Agent сохраняет резервную копию и атомарно меняет только `general.ad_tag`.
   Персональные теги `access.user_ad_tags` имеют приоритет и требуют отдельной
   проверки. Смена IP или порта во время диалога запрещает применение результата.
6. Проверить фактический hot reload и новые соединения. Успешная запись файла
   пока означает `TAG_WRITTEN_UNVERIFIED`, а не подтверждённый показ канала.
7. Проверить канал в целевом Telegram-клиенте отдельно для обычного MTProto и WEB.
   WEB Telemt передаёт логические MTProxy-потоки через общий relay; это не
   универсальный HTTP-прокси для произвольного браузерного трафика.

29 октября 2026 выполнен согласованный живой пилот: регистрация текущего
IPv4:9443, получение тега, назначение канала и запись через Agent подтверждены.
Реальный MTProxybot запрашивает `host:port`, показывает кнопку `IP tag` и
отвечает `New promoted channel has been set`. Inline-кнопки могут редактировать
существующее сообщение; адаптер принимает и правки, и новые ответы. Он учитывает эти ответы и
проверяет полный выбранный IP:порт перед назначением канала.

Тег записан через ограниченный helper; конфигурация сравнена с резервной
копией — изменено только значение `ad_tag`. Выполнен контролируемый перезапуск
Telemt с проверкой обоих listeners. Первоначальный пятисекундный предел готовности
оказался слишком коротким; защитный откат сработал, повторный запуск с 45 секундами
на старт прошёл. На сервере каталог Telemt принадлежит пользователю telemt:
helper требует CAP_DAC_OVERRIDE для атомарного создания файлов внутри него,
при этом ProtectSystem=strict и ReadWritePaths ограничивают запись этим каталогом.

Проверка показа канала в клиенте остаётся отдельным шагом. По сообщению
MTProxybot клиентам может потребоваться до часа. Ошибка спонсорства не
останавливает прокси.

## Фича заморожена — 30 октября 2026

По решению владельца разработка и включение автоматической регистрации через
MTProxybot и замены ad_tag отложены. Рабочая схема AutoIP: постоянные домен и порт,
сохранение текущего тега при смене IPv4. Восстановление сетевой доступности не
должно зависеть от диалога Telegram или получения нового тега.

Существующий адаптер сохранён; возобновление этой фичи требует нового указания
владельца. Разрешения Agent на запись ad_tag закрыты. Текущие настройки ноды,
регистрация и Telegram-сессия остаются нетронутыми. Сохранение показа канала
после смены IP проверяется отдельно при согласованном сетевом пилоте; неизменный
домен сам по себе не является доказательством серверной политики Telegram.
