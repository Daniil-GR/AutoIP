# Изолированное развёртывание Commander

## Границы

Каталог проекта не должен совпадать с существующими проектами. Compose project `autoip` имеет собственные сеть и PostgreSQL том. Не используйте host networking, существующие базы, чужие `.env`, systemd units и каталоги Telemt. Не запускайте `docker system prune`, глобальные перезагрузки Docker или изменение firewall.

HTTPS-настройка действующего reverse proxy — отдельное согласуемое действие. Сначала проверьте Commander локально и подготовьте отдельный виртуальный хост. Не запускайте `certbot --nginx` без проверки его изменений.

## Первичная настройка

Python 3.12, изолированное virtualenv и зависимости Commander. Если `venv` отсутствует, используйте отдельную среду/контейнер; не обновляйте системный Python действующих проектов.

```sh
python scripts/setup-local.py --public-url https://commander.example.com --telegram-admin 123456789
```

Файлы `.env` и `secrets/master.key` создаются однократно, без вывода паролей. Каталог `secrets` 0700; ключ 0600 принадлежит UID 10001 контейнера. Без root настройте владельца ключа перед запуском Docker. Сохраните мастер-ключ в отдельной зашифрованной резервной копии. Первичный пароль администратора находится только в закрытом `.env`; извлекайте его локально через защищённый терминал, не в чат и не в логи.

`--stage-credentials` предлагает скрытый ввод токена бота и Cherry API key и сохраняет только зашифрованные конверты. Это опционально, ключи также вводятся через панель.

```sh
docker compose config --quiet
docker compose up -d --build
docker compose run --rm migrate python -m commander.manage policy-init
```

Уже существующая v0.1 требует backup и ручного принятия схемы `adopt-v01`; обычный `migrate` не угадывает состояние БД. При наличии дублей machine_id уникальный индекс остановит миграцию — разберите дубли на копии до обновления.

Перед импортом bootstrap-файла подключите его отдельно только для операции импорта (он зашифрован, ключ уже смонтирован):

```sh
docker compose run --rm -v "$PWD/secrets/bootstrap-integrations.json:/run/bootstrap.json:ro" migrate python -m commander.manage import-bootstrap /run/bootstrap.json
```

Повторный импорт идемпотентен. Для изменения ключа создайте отдельную интеграцию и обновите привязки агентов. Не удаляйте старые секреты, пока не проверены использующие их процессы.

## HTTPS и 2FA

Публикуйте только отдельный виртуальный хост, передающий запросы на `127.0.0.1:18080`. Ограничьте запросы входа/enrollment и размер тела (64 KiB). Используйте TLS и HSTS после проверки сертификата. `AUTOIP_PUBLIC_URL` должен точно совпадать с Origin браузера.

Uvicorn доверяет forwarded-заголовкам только перечисленных IP. Укажите в `AUTOIP_TRUSTED_PROXY_IPS` реальный адрес доверенного reverse proxy, видимый контейнеру. Не ставьте `*` и не публикуйте внутренний API-порт в интернет. От этого зависит определение HTTPS и разрешение ввода ключей.

TOTP: создайте секрет локальным защищённым инструментом, добавьте его в приложение-аутентификатор без вывода в общий чат и смонтируйте отдельный файл 0600 в API. Укажите его путь через `AUTOIP_TOTP_SECRET_FILE`. Включение TOTP отключает вход через legacy Basic. Запасной доступ обеспечивается локальным управлением конфигурацией, не обходом 2FA через API.

## Бот

В настройках панели сохраните разрешённые Telegram User ID. Бот принимает только личные чаты этих пользователей. Настройки и кнопки сохраняются в PostgreSQL. Добавьте одну интеграцию `telegram_bot`; запуск:

```sh
docker compose --profile telegram up -d bot
```

Одновременно должен работать только один polling-процесс этого бота. Откройте бота и нажмите Start: далее действия доступны кнопками. Не вводите секреты в Telegram. Telethon — отдельный аккаунт и отдельная интеграция, не bot token.

## Backup и обновление

`scripts/backup.sh` создаёт закрытый pg_dump. Мастер-ключ и закрытая `.env` резервируются отдельно в зашифрованном хранилище. Регулярно проверяйте восстановление в отдельном Compose проекте с другим портом и томом.

1. Backup БД и защищённой конфигурации.
2. Собрать новую версию и проверить миграции на копии.
3. Остановить только AutoIP API/worker/bot, выполнить миграции.
4. Запустить API/worker, проверить heartbeat и очереди, затем bot.
5. При несовместимости восстанавливать предыдущий образ и backup, а не выполнять слепой downgrade.

`scripts/restore.sh` намеренно требует `--confirm-replace-autoip-database`; это согласуемое обслуживание, уничтожающее текущую БД AutoIP. Он останавливает только сервисы своего Compose проекта и не запускает Telegram автоматически.

## Перед эксплуатацией

Смотрите `IMPLEMENTATION_STATUS_RU.md`. Платный режим не включается настройкой панели. Нужны новый Cherry Agent, согласованный сетевой пилот с откатом, независимый мониторинг, безопасный DNS-провайдер или подтверждённый механизм изменения, Telethon-авторизация и реальная проверка MTProto/hot reload.


## RIPE Atlas: только SNI

В карточке агента задайте `sni_domain` (по умолчанию обнаруживается из `censorship.tls_domain`) и добавьте RIPE Atlas key через хранилище. Кнопка SNI отдельно запрашивает подтверждение расхода кредитов на одно измерение. При неоднозначном ответе POST задача остаётся `submission_uncertain`: повторная покупка измерения запрещена до ручной сверки в RIPE Atlas. Результат не участвует в решении о блокировке прокси.

## Авторизация Telethon и согласованный пилот

Создайте приложение для выделенного Telegram-аккаунта на https://my.telegram.org, права бота администратора к этому не относятся. Все чувствительные значения вводятся только локально скрытыми запросами:

```sh
docker compose run --rm -it migrate python -m commander.manage telethon-login dedicated-account
```

Команда отдельно запрашивает api_id/api_hash, телефон, код и при необходимости пароль 2FA; сохраняет зашифрованную StringSession. MTProto user secret добавьте отдельной интеграцией `mtproto` через защищённую форму. Привяжите обе интеграции к нужному Agent.

Только после согласования нового IP/канала и проверки состояния действующей регистрации:

```sh
docker compose run --rm -it migrate python -m commander.manage sponsor-agent AGENT_UUID --approve-new-registration
```

Потребуется ввести фразу с конкретными Agent ID и IP:port. Диалог сериализуется PostgreSQL advisory lock. Неизвестный результат регистрации не повторяется; требуется ручная сверка. Применение ad_tag отделено от состояния сети, и запись файла не считается подтверждённым hot reload.

Это реализация адаптера, а не подтверждение совместимости с текущим живым интерфейсом MTProxybot. Не выполняйте пилот на действующей регистрации без разрешения.


### Авторизация уже сохранённого Telegram-аккаунта

Если API-данные и телефон уже сохранены в зашифрованной интеграции со статусом `authorization_required`, повторный ввод не нужен:

```sh
cd /opt/autoip
docker compose run --rm -it migrate python -m commander.manage telethon-login --integration-id INTEGRATION_UUID
```

Команда отправит запрос входа только при её запуске оператором, предложит скрытый ввод кода Telegram и при необходимости пароля 2FA, после чего зашифрует StringSession в существующей записи. Новая дублирующая интеграция не создаётся. Без интерактивного терминала команда отказывается принимать секреты, чтобы избежать открытого ввода через fallback getpass. Код и пароль нельзя передавать в чат, через аргументы команд или переменные окружения.

Команда показывает указанный Telegram способ доставки: служебный чат на уже авторизованных устройствах, SMS, звонок или почта для входа. Ответ API означает принятие запроса, а не подтверждение фактической доставки. Если кода нет, пустой ввод запрашивает повторную отправку только при наличии `next_type` и после задержки `timeout`, заданных Telegram; за один запуск допускается один повтор. Если повтор недоступен, пустой ввод отменяет вход. SMS принудительно не включается. При ограничении частоты команда сообщает время ожидания; не перезапускайте вход многократно. Неподдерживаемый способ входа требует проверки в официальном приложении. Служебный ответ, код и хеш запроса не выводятся в журнал.

Если код не приходит, используйте QR в локальном терминале:

```sh
docker compose run --rm -it telegram-login python -m commander.manage telethon-login --qr --integration-id INTEGRATION_UUID
```

Сервис `telegram-login` отключает Docker-журналирование: QR содержит одноразовый секрет входа. Не запускайте QR через обычный `migrate`, не записывайте вывод терминала, не публикуйте QR или ссылку входа. На телефоне выберите нужный аккаунт, откройте **Настройки → Устройства → Подключить устройство** и сканируйте QR с экрана терминала. На сканирование отводится до минуты; если QR истёк, повторите команду. 2FA вводится скрыто только в терминале. Сессия сохраняется зашифрованно лишь после проверки совпадения номера аккаунта с сохранённым номером интеграции; при сканировании другим аккаунтом закрывается только созданная этой попыткой сессия. Сессии других приложений не используются.

### Проверка Dynadot

Сервис подписывает GET-запросы REST v2 через HMAC-SHA256 и Base64 по точному пути и query string отправляемого запроса; ключи находятся только в заголовке и подписи. Проверка соединения читает `/accounts/info`; список доменов доступен в карточке интеграции. Ответы аккаунта и контакты не записываются в журналы. Если Dynadot запрещает IP, разрешите исходящий IP Commander в Tools → API. Изменение DNS этим адаптером не выполняется.
