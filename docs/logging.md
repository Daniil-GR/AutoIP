# Журналы и диагностика AutoIP

## Где смотреть

В панели: «Логи / Инциденты». Аудит хранится в PostgreSQL, сохраняется после
перезапуска и входит в резервную копию БД. API /api/audit требует администратора.
История операций доступна также в боте; подробный разбор — через панель/сервер.

В каталоге установки Commander:

```sh
docker compose logs --since 24h --tail 500 commander worker bot
```

Docker уже ограничивает файлы приложений: до трёх файлов по 10 МБ на контейнер.
Это оперативные логи, а не постоянный архив: при пересоздании контейнера старые
файлы могут исчезнуть. Постоянная история событий находится в PostgreSQL.
Не публикуйте полный вывод логов внешних библиотек без проверки на секреты.

## Что сохраняется при ошибке

Для неожиданных ошибок API, обработки заданий мониторинга, итераций worker,
уведомлений бота и локальной команды Floating IP сохраняются error_id, время UTC,
компонент, этап, тип исключения и последние восемь мест вызова (файл/строка/функция).
В заданиях также сохраняются agent_id/task_id, в пилоте — operation_id.
API возвращает error_id вместо сырого исключения. По этому идентификатору можно
сопоставить ответ панели, журнал БД и логи контейнера.

Не записываются текст исключения, локальные переменные, строки исходного кода,
HTTP-заголовки, тело запроса, query-параметры, пароли, API-ключи и MTProto-secret.
При отказе самой БД запись остаётся в stderr с тем же error_id; отдельное событие
указывает diagnostic_storage_failed. Эта защита относится к новому механизму
AutoIP, а не является гарантией поведения всех внешних библиотек.

Root CLI сетевого пилота сохраняет безопасные stage/error_type/error_id/time
в last_error своего журнала /var/lib/autoip-floating-pilot/UUID.json, если журнал
уже создан и доступен; также печатает их в stderr. Ошибка до создания журнала
доступна в stderr. Состояния PREPARING/STAGED/COMMITTED и аварийный timer остаются
отдельными от диагностической ошибки. Смотреть также журнал своего unit:

```sh
journalctl -u autoip-agent -u autoip-floating-UUID.service --since '24 hours ago'
```

## Границы

Полный автоматический цикл восстановления ещё не включён. Наличие журнала
не означает, что любая ошибка автоматически исправится. Предполагаемую причину
устанавливают по типу исключения, месту вызова, состоянию операции и результатам
проверок; при необходимости добавляют адресную безопасную диагностику.
Не повторяйте заказ IP после таймаута без сверки уже созданных ресурсов.
При просьбе разобрать ошибку достаточно указать примерное время, ноду и видимую
проблему; секреты и пароли в переписку не нужны.
